Живой документ для реализации. Опирается на:

- [`product-discovery.md`](./product-discovery.md) — решения R1–R56
- [`design-brief.md`](./design-brief.md) — ТЗ для UI/UX
- [`promos-draft.md`](./promos-draft.md) — акция A (по умолчанию)
- [`дизайн/stitch_ui_ux_design_implementation/`](../дизайн/stitch_ui_ux_design_implementation/) — HTML-прототипы Stitch + [`atelier_dark_luxury_engineering/DESIGN.md`](../дизайн/stitch_ui_ux_design_implementation/atelier_dark_luxury_engineering/DESIGN.md)

**Статус:** в разработке по задачам 0→12. Стек: Astro static + PHP под базовые хостинги РФ.  
**Прогресс:** задачи 0–10 — done; дальше задача 11 (полировка).  
**URL языков:** `/ru/...` и `/en/...` (`prefixDefaultLocale: true`).  
**Режим работы:** одна задача → проверка → коммит → отчёт → ждать указаний.

## 1. Цель и рамки

**Цель:** многостраничный премиальный сайт заказа ремонта техники Gaggenau (заявка + звонок), RU + EN, без e-commerce, без админки, без прайса и онлайн-оплаты.

**Не делаем в v1:** калькулятор, блок цен «от …», B2B, блог, ЛК, слоты выезда, онлайн-оплата, админка заявок.

**Рабочее имя:** «Официальный сервис Gaggenau» (тестовое; может измениться — R18). Юридически жёсткие claim’ы «сертифицированный / BSH / официальный акт» из макетов в прод не тащим без подтверждения R2.

## 2. Стек под базовые хостинги РФ

Базовый shared-хостинг (Beget, Timeweb, REG.RU, SpaceWeb и аналоги) обычно даёт: **PHP + MySQL + статику по FTP/SFTP**, без Node.js SSR и без долгоживущего Next.js-процесса.

| Слой | Выбор | Зачем |
|---|---|---|
| Сборка фронта | **Astro** (static output) + TypeScript + Tailwind CSS | Контентный многостраничник, i18n, быстрая статика; `dist/` заливается на любой хостинг |
| Стили / токены | Tailwind + CSS variables из DESIGN.md | Совпадает с Stitch-прототипами |
| i18n | Astro i18n routing (`ru` / `en`) | R40 |
| Форма / API | **PHP** endpoint (`api/lead.php`) на том же хостинге | Работает на shared без Node |
| Уведомления | Telegram Bot API (cURL из PHP) + email (SMTP хостинга или `mail()`) | R35 |
| Хранение заявок | Опционально MySQL или append в защищённый JSON/log вне web-root | Админки нет (R36); достаточно уведомлений + лог |
| Локальная разработка | `astro dev` для UI; `php -S localhost:8080 -t dist` (или отдельная папка `api/`) для проверки формы | Обязательный просмотр после задач |
| Деплой | Сборка → FTP/SFTP `dist/` + `api/` + `.env`/config вне публичного доступа | Типичный сценарий РФ-хостинга |

**Почему не Next.js SSR / Vercel как основа:** на базовом РФ-хостинге нет runtime для Node SSR; статический экспорт Next возможен, но Astro проще и легче для контентного сайта + PHP рядом.

**Альтернатива только если позже будет VPS:** можно оставить Astro static и заменить PHP на маленький Node/Go — фронт не переписываем.

### Целевая структура репозитория

```text
/
  docs/                    # продуктовые и этот план
  дизайн/                  # исходные макеты Stitch (не деплоим как сайт)
  src/                     # Astro: pages, components, content, styles
  public/                  # статичные ассеты (изображения, favicon)
  api/                     # PHP: lead.php, config.example.php
  package.json
  astro.config.mjs
  tailwind.config.* 
  README.md
```

После `npm run build` → `dist/` (HTML/CSS/JS) + на сервер кладём `api/`.

## 4. Обязательный рабочий цикл после каждой задачи

После **каждой** завершённой задачи из §5:

1. **Локальный просмотр**
   - UI: `npm run dev` (Astro) → открыть затронутые страницы (desktop + mobile width).
   - Если задача трогала PHP/форму: поднять `php -S` на `api/` (+ при необходимости прокси/копию `dist`) и прогнать отправку.
2. **Мини-чек-лист задачи** — отметить пункты из блока «Проверить» у задачи; ничего критичного не оставлять «на потом» без записи в §7.
3. **Коммит в git** — один осмысленный коммит на задачу (или логически неделимый кусок), сообщение на русском или английском в стиле репо, с фокусом на *зачем*.
4. **Отчёт заказчику** простым языком (см. шаблон ниже) → **стоп и ждать** следующего указания. Не стартовать следующую задачу без команды.
5. **Не пушить на прод** без отдельного решения; remote — по запросу.

Исключения: чисто документационные правки в `docs/` — достаточно коммита, без обязательного `astro dev`, если UI не менялся.

### Шаблон отчёта после задачи

Писать для **оператора / заказчика**, который проверяет готовый сайт в браузере — без жаргона, с точными действиями.

1. **Что появилось на сайте** — простыми словами: какие экраны, блоки, кнопки.
2. **Куда смотреть** — точные адреса страниц + названия блоков/кнопок на экране.
3. **Чек-лист проверки** — пошагово: что нажать, что должно произойти, на что обратить внимание (desktop / узкое окно «как телефон»).
4. **Что уже работает / чего ещё нет** — явно разделить: чтобы не ждать отправку в Telegram, живые контакты и т.п., если это следующая задача.
5. **Коммит** — короткий идентификатор.
6. **Что дальше на выбор** — следующая задача по плану; ждать указания.
